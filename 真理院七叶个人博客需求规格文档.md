# 1. 项目目标

创建一个长期可维护的个人静态博客，用于：

1. 发布技术、研究、学习和创作类文章；
2. 展示个人项目与 Interactive Works；
3. 提供稳定的个人主页；
4. 通过 Markdown 进行低成本内容更新；
5. 支持数学公式、代码和技术表格；
6. 最终使用中国大陆静态站点基础设施部署。

目标 production architecture：

```text
Developer
   │
   │ git push
   ▼
GitHub Repository

   ▼

   ▼
Alibaba Cloud OSS
   │
   ▼
Alibaba Cloud CDN
   │
   ▼
Custom Domain / AliDNS
   │
   ▼
Users
```

# 7. Blog Content Model

使用 Astro Content Collection 管理文章。

每篇文章至少具有：

| Field | Required | Description |
|---|---|---|
| `title` | Yes | 标题 |
| `description` | Yes | 摘要 |
| `pubDate` | Yes | 发布时间 |
| `updatedDate` | No | 更新时间 |
| `tags` | No | 标签 |
| `draft` | No | 草稿 |
| `cover` | No | 封面 |

Example：

```yaml
---
title: "Symbolic Music Generation Notes"
description: "关于符号音乐生成模型的一些学习记录。"
pubDate: 2026-09-09
updatedDate: 2026-09-12
tags:
  - Music AI
  - Deep Learning
draft: false
---
```

Production 中：

```text
draft = true
```

的文章不得显示在公开文章列表、RSS 和 sitemap 中。

# 9. Mathematical Typesetting

## 9.1 Syntax

支持：

```markdown
$E=mc^2$
```

以及：

```markdown
$$
\mathbf{y} = \mathbf{W}\mathbf{x}+\mathbf{b}
$$
```

---

## 9.2 Rendering

要求使用适合静态构建的高质量数学渲染方案。

推荐技术方向：

```text
Markdown AST
   ↓
remark math
   ↓
rehype / custom transform
   ↓
KaTeX
```

具体 package 可以根据实施时 Astro 稳定版本调整。

---

## 9.3 Preserve Source

这是强制要求。

Markdown parser 得到的原始：

```tex
\mathbf{y} = \mathbf{W}\mathbf{x}+\mathbf{b}
```

必须在 render pipeline 中被保留下来。

不允许：

```text
Rendered KaTeX HTML
       ↓
尝试反向恢复 TeX
```

建议：

```text
math AST node.value
       ↓
data-math-source
       ↓
copy interaction
```

---

## 9.4 Copy Math Source

Display formula 必须具有明确的：

```text
Copy TeX
```

功能。

推荐 UX：

```text
┌────────────────────────────────────┐
│                             Copy ⧉ │
│                                    │
│        y = Wx + b                  │
│                                    │
└────────────────────────────────────┘
```

点击后：

```text
Clipboard
← raw TeX
```

并提供：

```text
Copied
```

反馈。

Inline Math 同样必须保留 source，并具有不明显破坏阅读体验的 copy mechanism。

Desktop、mobile、keyboard 均需要可操作。

# 27. OSS Permission Scope

GitHub deployment identity 应遵循 least privilege。

只允许目标 Blog Bucket 所需操作，例如：

```text
ListObjects
PutObject
DeleteObject
```

不要提供：

```text
AdministratorAccess
```

或全账号 OSS 管理权限。

---

# 28. CDN Cache Design

建议：

```text
HTML
→ short cache / revalidate
```

```text
hashed JS/CSS/assets
→ long cache
```

以利用 Vite / Astro content hash。

不要为每一次文章更新无条件 purge 全站 cache，除非部署方案确实需要。

# 38. Definition of Done

项目的 Definition of Done 是：

> 一个用户可以 clone repository，在干净环境中安装依赖、运行开发服务器、运行测试并构建完整静态网站；博客可以通过 Markdown 更新，数学公式和代码具有面向技术文章的完整阅读及复制体验；已有康威跳棋作品已经成为网站的一部分；GitHub CI 能验证每次修改；生产静态产物已经适合后续上传至阿里云 OSS；同时项目留下足够明确的内容维护和部署文档，使站点所有者未来不需要重新理解整个工程即可持续更新。
